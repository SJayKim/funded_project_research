2. 작업 DB를 바꾸기 전 원격 복원·SQLite 무결성·스키마를 검사하고 원본 사본/코드 SHA를 남긴다.
3. 실패 주입, 실제 DB 사본 보존, CI를 확인하고 복구 안내와 다음 단계 인계를 작성한다.

- 기존 workflow의 `git fetch ... || true`, `git show ... || rm -f ...`는 복원 오류 후 빈 DB 수집을 허용한다.

- 사용자의 미추적 감사 보고서와 개선 계획은 수정·커밋하지 않고 보존한다.

## 검증 결과

- 변경 전: Python 3.13.16, `python -m unittest discover -s tests -v` → 71개 실행, 70개 통과·유료 평가 1개 생략.
- 변경 후: 같은 환경에서 86개 실행, 85개 통과·유료 평가 1개 생략. 새 복원 테스트 15개가 추가되었다.
- workflow 원문 셸 리허설: 기존 명령은 손상 DB에서도 모의 수집/발송에 도달했다. 수정 명령은 손상/원격 장애/DB 파일 누락에서 수집 0·모의 SMTP 0·원격 DB 변경 0을 확인했다.
- 최초 생성 시 `--no-notify`, 기존 DB 정상 갱신, DB push 거절 시 실패 전파도 임시 Git 원격에서 확인했다. 실제 메일은 발송하지 않았다.
- actionlint 1.7.12: 수정 collect/test workflow 오류 0. shellcheck는 설치되어 있지 않아 별도 검사는 미실행이며 셸 명령은 위 리허설에서 실행했다.
- 원격 `data`의 DB를 별도 파일로 복원: 공고 75,221·알림 135,770건, 원본/복원/백업 SHA-256 동일. 키·시각·알림 이력을 포함한 파일 바이트 보존. 스키마/데이터 이행 없음.
- 복원 사본으로 정적 HTML 빌드 성공. 화면 변경이 없으므로 모바일/브라우저 UX 검증은 Phase 2 범위로 남긴다.
- 제품 판 `d274240`으로 로컬 커밋했다. GitHub push는 현재 OAuth의 `workflow` scope 부족으로 거절됐고 기존 SSH 인증도 실패했다. 원격 CI/PR은 미실행이며 로컬 검증과 구분한다. 계정 소유자의 인증 갱신 이후 재개한다.
- 후속 확인: 사용자의 인증 갱신 뒤 같은 브랜치 푸시와 초안 PR #1 생성을 완료했다. GitHub의 Python 3.13.18에서 85개 통과·유료 평가 1개 생략을 확인했다. 이전 중단 기록과 현재 상태는 [원격 CI 후속 인계](../sessions/phase-00-ci-2026-11-12.md)로 연결한다.
- 상세 검증과 원격 CI/배포 상태: [Phase 0 인계](../sessions/phase-00-data-safety-2026-11-12.md).
