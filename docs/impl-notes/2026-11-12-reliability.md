# 2026-11-12 신뢰성 개선

## Gate evidence

- 사용자 요청: “신뢰성 제고위해 plan 세워서 진행”. 직전 감사의 날짜 불일치·수집 정체·오래된 요약을 근거로 계획 수립과 수정을 요청했다.
- 승인 범위: 확인된 신뢰성 결함 수정, 회귀 검증, 기존 구조에서의 운영 적용. 사용자 요구를 코드 수정 없이 계획서만 만드는 것으로 축소하지 않는다.
- 실행안: `docs/planning/reliability-release-2026-11-12.md`.
- 기존 작업 보호: `improve/phase-00-data-safety`에서 별도 worktree/브랜치 `improve/dashboard-reliability`를 생성했다. 원 작업 폴더의 미추적 감사·UI 계획은 수정하지 않는다.
- 사람이 결정할 새 비용·신규 출처·실제 메일 수신자는 이번 범위에 없다.

## 판단 근거

- `CLAUDE.md`의 “테스트 없음” 안내는 실제 `tests/`와 CI에 맞지 않는다. 실제 unittest discover와 Python 3.13을 따른다.
- 기존 전체 로드맵의 순차 세션 대신 최신 사용자 요청의 신뢰성 목표에 맞는 수정을 배포 단위로 묶는다. 화면 재설계는 포함하지 않는다.
- 공식 출처의 존재와 최신성은 별개다. 마지막 수집일 최댓값을 전체 정상 상태로 표시하지 않는다.

## 검증 기록

- Python 3.13: 104개 실행, 103 통과·유료 평가 1 skip. 신뢰성 전용 18개는 ResourceWarning을 오류로 설정한 상태에서도 통과했다.
- 실제 운영 DB 사본 75,221건·알림 135,770건 전수 보존, 읽기 전용 dry-run 해시 불변, 스키마 2회 이행, 정정 재실행 검증.
- 공식 원문 20건 전부 기간 확인. 알려진 날짜 오류 2건 정정, 시각 보강, 오래된 일정 발췌 숨김.
- Chromium에서 KST 자정 전후와 마감 필터, 원문 링크·검색·모바일 375px 확인. 콘솔 오류 없음.
- 원문 조회는 TLS 체인·호스트 검증을 켠 상태로 확인했다. 기존 CERT_NONE 경로를 제거했다.
- 기존 테스트의 지오차단 info 강제와 근거 없는 발췌 캐시는 실제 감사 결함을 보존하므로 기대값을 수정했다. 원본 발췌 보존과 검증된 캐시 유지 테스트는 유지한다.
- 신규 필드의 빈 기본값·내부 해시는 정적 HTML에 보내지 않아 같은 사본의 출력은 약 49.9MB다(수정 전 공개본 약 56.3MB). 페이지네이션은 후속이다.
