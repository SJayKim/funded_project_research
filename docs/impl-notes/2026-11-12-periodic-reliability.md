# 주기적 신뢰성 점검

사용자 요청 “매번 신뢰성있게 주기적으로 체크하게 만들어줘”에 따라 수집 후 검사와 별도 정기 점검, 점검 누락 감시를 연결했다. 브랜치는 `improve/continuous-reliability`이며 기존 신뢰성 배포 위에서 작업했다. 공고 의미 전체를 자동으로 보증하지 않고 실제 검사 범위·확인 시각·실패를 표시한다.

## 실행 계약

| 실행 | 한국 시각 | 검사와 결과 |
|---|---|---|
| 기존 수집 | 매일 09:00 | 수집 후 원문 재확인·전체 DB 검사·점검 기록 저장·배포 대조 |
| 신뢰성 점검 | 매일 00:17·06:17·12:17·18:17 | 출처 조회·원문 최대 100건·전체 DB 검사. 공고 신규 적재·메일·LLM 호출 없음 |
| 점검 누락 감시 | 매시간 43분 | 공개 `reliability.json`의 완료 기록이 8시간 이내인지 확인. 누락·미래 시각·오래된 기록이면 실패 |
| UI 변경 배포 | 기존 push/수동 실행 | 배포한 HTML 바이트와 점검 JSON을 빌드 산출물에 대조 |

정기 점검 단계에는 SMTP·LLM 인증값을 전달하지 않는다. `health_only=true` 수동 실행도 같은 경로를 사용한다. 기존 09:00 수집의 알림 계약은 유지한다. 수집/DB/Pages는 같은 실행 그룹에서 직렬화하고 감시는 읽기만 한다. 전체 실행은 35분, 원문 조회 단계는 20분 이내로 제한한다.

GitHub 예약 실행은 지연되거나 누락될 수 있으므로 정시 완료를 보증하지 않는다. 화면도 현재 시각 기준으로 8시간 경과를 표시한다. 같은 GitHub 플랫폼 전체가 멈추면 감시 실행도 지연될 수 있다. 근거: [GitHub 예약 실행 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## 대상 순환과 판정

원문 신청기간 검사는 기업마당·K-Startup의 마감 전/미확인 공고를 대상으로 한다. 최근 24시간에 확인한 공고는 건너뛴다. 마감 14일 이내·기술 공고·정보 상충에 3/4, 나머지에 1/4를 우선 배정하고 남은 자리는 채운다. 같은 그룹에서는 가장 오래 시도한 공고부터 처리한다. 실패도 `recheck_attempts`에 기록하며 6시간 안에는 자동 재시도하지 않는다. 과거 오류 표본 중 이미 마감된 공고는 7일 간격으로 확인한다. 명시적 `--key`는 순환 정책보다 우선한다.

전체 DB 검사에서는 무결성·공고 식별자·날짜 상태·확인 시각·현재 검증값 불일치·원문 링크 형식·임박 공고의 원문 미확인을 확인한다. 누락된 마감/원문, 오래된 요약·발췌, 기간 파서 미지원 출처는 건수를 기록한다. 원문 조회 결과 파일 누락·유효하지 않은 결과·미확인 응답도 성공으로 처리하지 않는다.

각 실행의 `reliability_checks` 기록과 JSON artifact, Actions 요약을 남긴다. 문제가 있으면 점검 근거와 기존 데이터를 배포한 다음 실행을 실패로 표시한다. 별도 감시는 점검이 살아 있는지를 확인하므로 최근 기록의 데이터 판정이 `attention`이어도 누락으로 오인하지 않는다. 개인의 Actions 알림 수신 설정은 변경하지 않았다.

## 검증

로컬 자동 테스트는 전체 124개 중 123 통과·유료 평가 1 skip이다. 신규 15개는 ResourceWarning을 오류로 설정해 통과했다. 실패 후 다음 대상 선택, 일반 공고 순환, 최근 확인/재시도 간격, 보고서 누락, 잘못된 시각·링크, 실패 보고서 보존, 공개 기록 만료·배포 불일치·전파 지연 재시도를 검사했다.

운영 DB 사본에서 원문 100건 중 98건을 확인했고 2건은 미확인으로 남겼다. 공고 75,221건·알림 135,770건과 공고 ID·최초/마지막 수집일을 보존했다. 이미 존재하던 출처 장애와 14일 내 원문 미확인 143건 때문에 데이터 판정은 `attention`이다. 이를 정상이라고 덮지 않았다.

Chromium에서 검색·페이지 이동·상세 펼침·320~1440px와 8시간 경과의 자동 경고 전환을 확인했다. 로컬 서버에서 점검 JSON과 약 50MB HTML 바이트 일치 검사도 통과했다. 근거는 작업 폴더 `.gstack/periodic-reliability/`와 `.gstack/dashboard-verification/`에 보관한다. 운영 활성화는 CI 통과 후 병합·수동 1회 실행·별도 감시 실행·공개 화면으로 확인한다.
