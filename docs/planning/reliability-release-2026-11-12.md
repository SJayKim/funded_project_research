# 정부과제 정보 신뢰성 개선 실행안

2026-11-12 감사에서 확인한 잘못된 신청 판단을 먼저 차단한다. 기존 17단계 개선안은 전체 로드맵으로 유지하고, 이번 배포는 날짜·최신성·수집 결과·파생 정보·근거 있는 정정을 묶는다. 별도 PR #2에서 병합한 검색 중심 화면에 이 규칙을 적용한다. 이메일 대기열 개편은 후속 작업이다.

## 목표와 검증

| 순서 | 결과 | 통과 기준 |
|---|---|---|
| 1 | 한국 현재 시각에 맞는 마감·접수 상태 | 날짜/시각 경계·잘못된 날짜·종료 상태를 Python/JS 공통 사례로 검증 |
| 2 | 수집 실패와 오래된 공고가 드러남 | 출처별 정상/빈 결과/부분/실패, 0건 실패, 페이지 상한, 미확인 공고의 진행중 제외 |
| 3 | 과거 요약이 현재 사실처럼 보이지 않음 | 입력 변경 시 요약/발췌 무효화, 입찰/마감 불명 문구, 추출로 확인 시각 갱신 금지 |
| 4 | 공식 원문으로 확인한 정정과 배포 | DB 사본에서 변경 근거·멱등성·ID/최초수집/알림 보존, 원문 표본, CI·공개 페이지 확인 |

현재 기준선은 75,221건, IRIS 0건, 원문 마감 불일치 2건이다. 기본 목록 1,636건 중 마감 불명 1,132건이다. 이 수치를 전체 오류율로 사용하지 않는다.

## 범위와 정책

- 기존 Python 표준 라이브러리·SQLite·정적 HTML을 유지한다. 신규 출처·유료 LLM·서버 계약·메일 시험 발송은 포함하지 않는다.
- 날짜만 있는 마감은 한국 날짜 종료까지, 시각 있는 마감은 해당 시각까지로 처리한다. 접수 시작 전·마감·확인 필요를 구분한다.
- 매일 수집 계약에 따라 개별 공고 확인 후 48시간을 넘으면 재확인 대상으로 표시한다. 기존 last_seen은 검증 시각으로 소급 승격하지 않는다.
- 공식 원문 날짜 정정은 구조화된 신청기간만 사용한다. 자유문 날짜 추측은 금지한다. 실패/충돌은 확인 필요로 남긴다.
- 기존 공고·알림 이력은 보존한다. 정정 작업은 이메일을 보내거나 신규 알림 이력을 만들지 않는다.
- 운영 출처 접근 점검은 `health_only`로 수행한다. 공고·알림 이력과 유료 LLM을 건드리지 않고 출처별 실제 응답 상태를 기록한다.
- 외부 API 정상화와 3회 정기 실행 관찰은 실제 결과를 얻은 뒤 완료로 판정한다. 코드·CI 완료를 외부 출처 전체 복구로 간주하지 않는다.

## 후속 순서

다음은 운영 환경의 K-Startup·IRIS 접근 복구, 나라장터 정정 차수와 장기 접수 갱신, 분류·중복 제거, 알림 대기열/누락 보충이다. 현재 배포의 불확실성 표시가 이 작업을 대신하지 않는다.
